# 人物杂交规则

杂交的目标是组合“机制槽位”产生新的因果矛盾，不是把两个知名人物的姓名、外貌和名场面拼在一起。

## 1. 输入资格

- 只有 `Gold` 可作为完整母卡；`Silver` 只能输出已经通过质量门的具体槽位；`Reference` 不进入正式杂交。
- 每个输入槽位必须有来源卡 `card_id`、层 ID 和置信度。
- 年龄未知或未成年卡不得输出情色化视觉槽位。
- 输入卡的原作专有姓名、地名、组织、道具、台词、事件顺序和结局默认不可遗传。

## 2. 可杂交槽位

| 槽位 ID | 内容 | 主要来源层 |
|---|---|---|
| `visual_signature` | 1—3 个身体/姿态/衣着记忆点及其剧情功能 | `V` |
| `identity_contrast` | 公共身份与私人需求的张力 | `F/M` |
| `long_term_lack` | 长期匮乏及其成因 | `M` |
| `first_crossing` | 第一次跨越的自我边界 | `M` |
| `immediate_reward` | 越界后的即时奖励 | `M` |
| `power_method` | 在关系中获得和维持权力的方法 | `M` |
| `secret_leverage` | 获取、保存和使用秘密的方式 | `F/M` |
| `class_desire` | 阶层目标、入口和恐惧 | `M/H` |
| `escalation_logic` | 退出为何更痛、下一次如何加码 | `M/P` |
| `fatal_miscalculation` | 持续误判的变量 | `M` |
| `cost_structure` | 机制走到底的代价 | `M/P` |
| `urban_container` | 2020年代中国城市、职业、平台和法律容器 | `H` |

## 3. 组合必须有因果方向

每次杂交至少包含两个来源，但不能做平均混合。用“目标—手段—阻力—升级—代价”说明分工，例如：

- A 卡提供 `long_term_lack`；
- B 卡提供 `power_method`；
- C 卡可提供 `urban_container`；
- 新人物必须产生一个任何单一卡都没有的“涌现矛盾”。

禁止写“各取一半”“兼具二人优点”而不说明因果。

## 4. 兼容性测试

### 机制兼容

- 目标与手段是否能在同一社会位置共存？
- 即时奖励是否真的强化该人物的长期匮乏？
- 权力方法是否能接触到秘密或资源？
- 加码逻辑是否由前面的奖励和风险自然推出？

### 生产性冲突

至少保留一组内部冲突，例如：守序身份需要公开透明，但秘密权力依赖隐瞒。冲突必须能反复制造选择，不能在人物设定第一段就被解决。

### 现实容器

现代职业、婚姻、平台、隐私、财务和法律条件必须允许这些机制发生。若只能靠原作制度运行，说明 H 层尚未完成。

## 5. 禁止组合

- 直接复制任一原作的事件顺序、核心关系组合和结局；
- 用同一来源人物同时提供视觉、欲望、越界、权力、秘密、加码和代价，仅换职业与姓名；
- 把互相矛盾的动机简单并列，不解释何时切换；
- 把“胸大、腰细、腿长”等通用外观当成杂交价值；
- 把未成年或年龄未知角色的视觉特征转换成成人情色资产；
- 为满足杂交槽位而把 `UNKNOWN` 补写成事实。

## 6. 来源占比与防换皮

用槽位数量做提示而非机械版权判断：若一个来源提供超过一半的核心机制槽位，或同时提供“匮乏—第一次越界—即时奖励—加码—代价”完整链，默认判 `HIGH_CLONE_RISK`，必须拆换至少两个因果核心。

至少满足：

1. 新人物的现代职业与资源容器不是原作功能的表面改名；
2. 三个剧情发动机中至少两个无法映射到任一来源的专有情节；
3. 新人物最大错误判断由组合后的矛盾产生；
4. 视觉签名与任何来源卡都不完全相同；
5. Anti-Clone 最近邻对比包含来源卡和全库最近邻。

## 7. 杂交记录模板

| 字段 | 内容 |
|---|---|
| `hybrid_id` | 稳定唯一 ID |
| `purpose` | 该组合要解决的剧情需求 |
| `donor_card_ids` | 来源卡列表 |
| `slot_provenance` | 每个槽位来自哪张卡、哪一层 |
| `compatibility_result` | 目标、手段、奖励、升级是否连通 |
| `productive_conflict` | 新的内部冲突 |
| `emergent_trait` | 单一来源不存在的新机制 |
| `forbidden_inheritance` | 明确排除的原作专有物 |
| `clone_risk` | `LOW / MEDIUM / HIGH_CLONE_RISK` |
| `adult_visual_gate` | `PASS / RESTRICTED / NOT_APPLICABLE` |
| `quality_result` | `PASS / REVISE / REJECT` |

## 8. 输出审计

- 所有槽位可追溯；
- F、Interpretation、Adaptation 未混写；
- 机制链闭合且出现新矛盾；
- 现代容器通过现实校验；
- 未继承原作专有剧情；
- 通过视觉和机制双重 Anti-Clone；
- 生成的是一个可行动的人，而不是标签集合。
