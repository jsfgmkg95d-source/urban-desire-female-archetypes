# 开源价值与发布条件

评估日期：2026-09-29。内容基线：`3fe5387`。本轮扫描全部机器记录，并深入抽样人物卡与来源；没有逐条重新核验全部原著，也没有做外部文本相似度比对。

## 判断

**有开源价值，适合定位为“可追溯的人物机制研究与创作工具包”。当前更适合准备一个可信的小版本，再公开发布。**

最有价值的资产是“来源 → 事实 → 可反驳解释 → 现代设计 → 差异审阅 → 检索摘要”的方法和工作路径。30 张卡提供了样本规模，但部分卡的证据、评分和现代改编仍需复核。现有材料不足以证明它是独立核验的文学数据库，也不足以承诺小说质量或商业回报。

## 实际资产与可用程度

| 资产 | 当前状态 | 价值与限制 |
|---|---|---|
| 方法、字段契约、模板与技能 | 已有完整九层框架与 24 个一级原型 | 可迁移到其他人物与题材；部分硬门仍较繁重 |
| 人物内容 | 30 卡，内部定级 27 Gold / 3 Silver | 有实用分析，但质量不均；Gold 不代表外部认证 |
| 来源覆盖 | 中国经典 20、世界经典 7、神话史诗 3 | 样本集中，尚不能代表影视、动漫、游戏或全部都市人物 |
| 机器检索 | JSONL、R 胶囊与十个 Markdown 视图 | 可供本地工具接入；摘要仍依赖人工复核 |
| 维护工具 | 本轮补入确定性构建、过期检查、统一校验与 CI 配置 | 减少维护漂移；不证明分析内容正确 |
| 原创组合规则 | 槽位、冲突、禁止继承与最近邻框架已建立 | 规则有价值，实际组合成品与作者反馈仍不足 |
| 产品界面与第三方导入 | 未实现 | 并非当前内容库的必要条件，需有实际需求再开发 |
| 用户需求与商业验证 | 未验证 | 不能用文件数、Gold 数或模型自评替代真实使用效果 |

原角色年龄状态为 9 个 `CONFIRMED_ADULT`、4 个 `CONFIRMED_MINOR`、17 个 `UNKNOWN`。未知项保留和年龄限制是方法优点；H4 的成年现代设计不能替代原角色年龄证据。

## 谁可能用它，差异在哪里

最直接的用户是中文小说作者、人物设定与写作工作流开发者，以及需要给 AI 提供来源和使用边界的人。价值在于减少“聪明、漂亮、拜金、强势”等标签式生成，让作者能比较奖励、权力、秘密、退路与代价。

相邻生态已经有角色卡与创作前端。例如 [SillyTavern](https://github.com/SillyTavern/SillyTavern) 提供与模型交互的本地界面，[Character Card V3](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md) 定义角色卡交换格式。这说明角色资料与工具接入已有生态，但不能由此推出本项目的用户数量。

从这些项目的公开说明与本库字段作比较，本库可发展的差异是**可回读的证据、因果机制与防换皮审阅**。这是定位判断，不是全球唯一性结论。本库目前也未兼容上述卡片交换格式。

建议保留现有的都市男频定位，同时让入口清楚解释“欲望”的广泛含义。未来可把“人物机制研究”作为公共方法，把成年视觉设计作为明确标注的应用专题；是否拆包应在下一次内容修订中决定。

## 许可建议与权利边界

“公开可见”与“授予开放使用权”是不同状态。GitHub 说明，真正作为开源项目分发，需要许可他人使用、修改和再分发；没有许可证时，默认版权规则仍适用。[GitHub 许可证说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)

本项目主要是研究内容与数据，附带维护代码。建议按资产分别选择许可，以下仅是方案，本轮没有写入授权文本：

| 范围 | 建议方案 | 发布前要明确 |
|---|---|---|
| 自有权利的原创分析、模板、说明与数据表达 | CC BY 4.0 | 署名方式、修改标记、排除的第三方材料 |
| 维护脚本 | MIT | 权利人署名与代码授权范围 |
| 原作短摘录、译文、网页内容与第三方材料 | 分项登记，不由本库重新授权 | 来源权利、版本、地域、引用范围和实际使用依据 |

CC BY 4.0 允许分享、改编和商业使用，要求适当署名及修改标记；既有许可的自由不能因作者以后改变意愿而收回。[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) MIT 允许代码的使用、修改与分发，并要求保留版权和许可声明。[MIT 说明](https://choosealicense.com/licenses/mit/)

许可者只能授予自己有权授予的权利，需明确标记未纳入许可的第三方内容。古典原作与实际使用的现代译本或页面内容可能涉及不同权利，不能只凭作品年代宣布统一开放。[CC 法律文本的许可者说明](https://creativecommons.org/licenses/by/4.0/legalcode)

若希望禁止商业使用，可另行选择内容许可，但不应把这种限制描述为符合 OSI 定义的软件开源许可；OSI 定义要求不限制特定用途，包括商业使用。[Open Source Definition](https://opensource.org/osd)

## 最小发布路径

1. **先选 3—5 张示例做实。** 以潘金莲、阎婆惜、王熙凤等候选开始，逐条读源，修 claim 映射、评分理由和现代设计；完成后才称为公开示例。
2. **发布方法、模板、工具与复核后的示例。** 其余卡继续保留为有范围说明的研究资料，不用 27 Gold 作质量宣传。
3. **展示一个完整原创组合案例。** 从需求、召回、回读、槽位分工到新矛盾和差异审阅，明确它如何改变实际写作决策。本轮检索示例只完成比较步骤。
4. **确定许可与内容范围。** 选择代码和内容许可、署名方式与第三方排除清单，再决定是否将仓库改为公开。
5. **请少量作者试用并记录结果。** 比较普通提示词与使用本库的设计，记录检索时间、重复程度、需要纠正的事实和采用了哪些槽位。

在这些结果出现前，优先提高证据与解释质量，不必扩到 500 人、搭大型网站或增加多个生成模型。规模应服务于实际机制空白和使用需求。

- 修复换行敏感校验，移除固定 30 人和固定历史批次的运行限制。
