# 使用指南

把一个剧情需求变成一组可比较的人物机制，再判断哪些部分能进入原创设计。

## 1. 先问剧情需要什么

比起“给我一个聪明、漂亮的女人”，可检索的问题是：她想拿到什么资源，靠什么行动拿到，第一次成功为何让她继续，什么时候会失去退路？

按需求选择[检索导航](../indexes/README.md)：

| 问题 | 入口 |
|---|---|
| 相同欲望为何走向不同代价？ | 欲望机制、一级原型 |
| 她如何改变别人的选择？ | 权力方式、秘密杠杆、关系机制 |
| 哪种社会位置允许机制发生？ | 现代角色、身份反差 |
| 什么能重复触发冲突？ | 剧情发动机，再回读 P |
| 出场时如何辨识、误读她？ | 视觉签名，同时检查原角色年龄与 H4 标记 |

## 2. 用 R 召回，再回读完整卡

R 提供一句话母体、视觉签名、欲望链、权力接口、都市容器、组合建议、禁止写法与调用串。它适合比较候选，不能当成新的事实来源。

命中后回读：

1. **F 与来源**：这个行为在哪个版本发生，年龄与未知项是什么？
2. **M**：奖励怎样改变下一次选择，有无反证？
3. **P / H**：剧情是否能反复发生，现代职业与制度是否允许？
4. **X / A**：能继承哪些槽位，哪些属于原作专有物，与最近邻差在哪里？

`Gold` 是内部定级，`Silver` 只能使用已经通过质量门的具体槽位，`Reference` 留作资料研究。已知内容问题见[评估](open-source-assessment.md)，使用前仍须审阅相关卡片。

## 3. 区分原角色与现代设计

`FACT` 说明原作发生了什么；`INTERPRETATION` 解释机制；`ADAPTATION` 提出新的现代设计。`UNKNOWN` 表示证据不足，不能把它读成“没有”。

原角色的年龄由 F 和来源决定。H4 是单独声明为 25 岁以上的现代设计；原角色未知或未成年时，V 的限制仍然生效。视觉索引里来自 H4 的字段只描述现代设计，不证明原著身材或意愿。

## 4. 输出一个可复核的设计单

记录“需求、候选 ID、选中槽位、所属层、依据、未继承项、新矛盾、代价和待验证现实条件”。至少使用两个来源的不同机制槽位，并检查组合后的因果能否连通。

避免一次继承某个人物完整的“匮乏 → 越界 → 奖励 → 加码 → 代价”链。职业换名不能消除原剧情的映射关系。完整过程见[检索示例](../examples/retrieval.md)与[组合规则](../references/hybridization-rules.md)。

## 5. 交给 AI 时

让 AI 读取 [SKILL.md](../SKILL.md) 和 [AGENTS.md](../AGENTS.md)，给出明确的卡片范围与任务。仅要求检索时，输出候选和匹配依据；要求修订时，先读卡片与来源，再同步机器摘要与索引。

可以这样提出请求：

> 为“掌握秘密后争取退出条件，但信息优势不能保证安全退出”找两到三张候选卡。只检索和比较，返回 card_id、相关层、来源定位、关键差异和使用限制。回读完整卡片后再给机制槽位建议。

AI 可以直接读取公开导航与机器目录，也可克隆仓库运行 JSON 检索命令，或连接本地 stdio MCP。完整步骤见[AI 接入指南](ai-integration.md)。技能安装需要完整仓库；本版不托管远程 HTTP 检索服务，也没有第三方角色卡格式导入器。
